# SEO-Friendly Filenames

A filename identifies a resource on a website. Descriptive names can help people understand a link before opening it and can provide useful context about an image or document. Filename wording is a small part of SEO, however; it cannot compensate for thin content, inaccessible files, or a poor user experience.

## Write filenames that describe the resource

Prefer names that are short, meaningful, and specific. Use ordinary words separated by hyphens for web URLs, and avoid long strings of random characters when a descriptive name is practical.

Examples:

| Less helpful | More descriptive |
|---|---|
| IMG_0048.webp | css-grid-three-column-layout.webp |
| file-final-v7.pdf | html-forms-reference.pdf |
| page123.html | javascript-array-filter-example.html |

The examples are illustrative. Use a filename that accurately describes the actual file, not one chosen only to include a popular search term.

## Image filenames

For images, name the subject or purpose clearly before uploading. A screenshot used to explain a CSS Grid layout might be called css-grid-layout-example.webp. If an image is replaced, keep the filename stable when practical to avoid unnecessary URL changes.

Filename text and alt text serve different purposes. The filename identifies the file; alt text communicates the relevant information of an image to people who cannot see it. An informative image should have concise, accurate alternative text. A purely decorative image can usually use an empty alt attribute.

Do not stuff a filename with many variations of the same phrase, such as css-grid-css-grid-layout-best-css-grid.webp. It is harder to maintain and does not create meaningful value.

## Filenames for downloads and documents

A downloadable resource should be identifiable before someone saves it. Names such as html-forms-cheat-sheet.pdf are clearer than download1.pdf. Keep the file's title and content consistent with its name, and provide a surrounding page that explains what the download contains.

For frequently updated resources, consider including a version or date only when it genuinely helps users distinguish editions. Avoid creating unnecessary duplicate files just because the wording changed.

## Filenames and page URLs

For static HTML pages, the filename may be part of the public URL. For sites built with a content management system or framework, the visible route may be configured separately from the source filename. For example, an MDX source file can be named differently from the URL generated by the site's routing configuration.

Before renaming a public file, determine whether its URL will change. If an established URL must change, map the old URL to the closest relevant new destination with a permanent redirect, update internal links and sitemap entries, and check the result. Avoid changing filenames on published resources without a clear benefit.

## Technical details to check

- Use consistent lowercase naming for web resources where your system supports it.
- Prefer hyphens between words in public URL slugs.
- Avoid spaces and characters that require confusing URL encoding.
- Check for case-sensitive path differences on the production hosting platform.
- Make sure the server returns the correct content type and status code.
- Use appropriate image dimensions and compression; the filename does not make a large image load faster.
- Keep internal references accurate when a file is moved or replaced.

Not every file should be renamed. If a resource is already live and works correctly, changing its name solely for SEO may introduce broken links and offer little benefit.

## A practical workflow

Suppose you are publishing a diagram for a tutorial about network topologies. Before upload, name the file network-topology-diagram.webp. Add appropriate alt text if the diagram conveys information, include a caption when it helps, compress the image without harming readability, and link to it from the relevant lesson. If the file is already referenced on other pages, verify those references after any change.

## Checklist

- [ ] The name accurately describes the resource.
- [ ] It is readable and not overloaded with keywords.
- [ ] Public URLs remain stable where possible.
- [ ] Image alt text is written for accessibility, not keyword repetition.
- [ ] The file is optimized for its purpose and delivered correctly.
- [ ] Any moved resource has updated links and an appropriate redirect.

## Key takeaway

Relevant filenames improve clarity and maintenance, and may give search engines additional context. Treat them as a supporting detail in a broader strategy built around useful content, accessible resources, and consistent URLs.
